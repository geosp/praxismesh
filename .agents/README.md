# Project-specific agent tooling

`.agents/` is the source for PraxisMesh-specific skills and agent definitions.
Reusable planning and review skills, their helper/templates, and the three
reviewer agents come from the owner-maintained Skill Central repository. See
[planning and installation](../docs/development/planning.md). They are not copied
or generated here and are not dependencies of public CI or runtime services.

| What | Canonical source | Discovery |
| --- | --- | --- |
| Project guidance | AGENTS.md | Codex/Copilot directly; Claude through CLAUDE.md |
| Project skills | .agents/skills | Codex directly; Claude/Copilot through .claude/skills symlink |
| Project verifier agent | .agents/agents/verifier.md | Per-harness files generated by sync_agents.py |
| Shared planning/review suite | Skill Central skills/ | Owned per-skill user links |
| Shared reviewer agents | Skill Central agents/ | Codex owned config_file references; other harnesses owned user links and native variants |

## Local skill names

Use lowercase `<domain>-<capability>` names matching the folder and frontmatter.
Domains include github-, plan-, spec-, review-, verify-, docs- and dev-. Externally
maintained skills keep their canonical names; do not create local aliases that
cause duplicate discovery. The three local skills are listed in
[skills/README.md](skills/README.md).

## Local agent generation

Edit only `.agents/agents/*.md`, then run:

```bash
uv run .agents/sync_agents.py
uv run .agents/sync_agents.py --check
```

The generator writes `.claude/agents/*.md`, `.github/agents/*.agent.md` and
`.codex/agents/*.toml`. It prunes only its own generated files. Never edit generated
files or write Skill Central's managed personal destinations through this tool.
The [agent format](agents/README.md) describes per-harness configuration blocks.

## Session permissions

Repository settings, protection, secrets, force pushes, default-branch pushes and
merges remain prohibited for agents. Claude uses `.claude/settings.json` as an
additional guardrail. Copilot role restrictions depend on tool grants and
instructions. Current Codex agents inherit the parent session's permission policy;
agent files do not create an independent sandbox. See the
[session roles](../docs/reviews/README.md#session-roles-and-permissions).

The verifier remains project-owned and runs in a disposable checkout. Shared
reviewers receive only committed inputs in fresh sessions for phase gates. Never
claim a tool permission is enforced merely because a role's prose asks for it.
